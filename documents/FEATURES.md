# 기능 안내

[문서 목차로 돌아가기](./INDEX.md)

## 데스크톱

- Windows XP Luna 스타일의 자유 배치 창을 제공합니다.
- 창 포커스, 이동, 크기 조절, 최소화, 최대화, 복원과 작업 표시줄 전환을
  지원합니다.
- 시작 메뉴에서 프로그램을 실행하고 Cloudflare Access에서 로그아웃할 수
  있습니다.
- 바탕 화면, 탐색기, 휴지통, 창과 작업 표시줄에 XP형 메뉴를 제공합니다.
- 프로그램 창의 위치·크기·상태·쌓임 순서는 D1에 저장됩니다.

데스크톱 UI는 1024×640 이상의 화면을 대상으로 합니다.

## 모바일

- 초기 Android 스타일 홈 화면과 뒤로·홈·메뉴 탐색을 제공합니다.
- 바탕 화면, 내 문서, 내 컴퓨터와 휴지통을 탐색할 수 있습니다.
- 폴더 상세 정보를 확인하고 폴더별 정렬 설정을 변경할 수 있습니다.
- 이미지·영상을 보고 파일을 다운로드할 수 있으며, 이미지 뷰어에서는 같은
  폴더의 이미지를 좌우 스와이프로 이동할 수 있습니다.
- 텍스트 파일은 읽기 전용 메모장으로 열 수 있습니다.
- 바탕 화면·내 문서의 기존 이미지를 계정 공용 홈 배경화면으로 지정할 수
  있습니다.
- 메모·체크리스트 로컬 초안을 작성한 뒤 D1 프로그램 문서로 저장할 수
  있습니다.

포인터가 거칠고 화면 너비 또는 높이가 767px 이하인 환경에서 모바일 UI를
사용합니다. 모바일에서는 데스크톱에서 열어 둔 프로그램 창을 자동으로 열지 않습니다.
새 프로그램은 한 번에 하나의 로컬 초안으로 보관되며 로그아웃 후에도
유지됩니다. `파일로 저장`을 실행해야 D1 프로그램 문서가 생성됩니다.

모바일 파일 시스템은 탐색·보기·다운로드 중심입니다. 다음 작업은 데스크톱에서
수행합니다.

- 업로드와 폴더 생성
- 이름 변경과 이동
- 휴지통 이동·복원·영구 삭제

## 프로그램

- 메모: 마크다운 작성, 미리보기와 저장
- 체크리스트: 문서별 일간·주간·월간 반복, 체크 시각 표시, 항목 편집과 이력 조회
- 저장소 상태: R2·D1의 현재 사용 상태 확인
- 이미지 API 프로필: 저장 경로·파일명·허용 MIME과 수신 기록 관리
- 관리자: 게스트 접속 허용 여부와 항목별 공개 상태 관리

메모와 체크리스트는 파일로 저장할 수 있습니다. 저장소 상태, 이미지 API
프로필과 관리자는 파일로 저장되지 않는 단일 프로그램입니다. 내장 프로그램은
마지막 창 배치를 유지하지만 다음 접속 때 자동으로 열리지 않습니다.

데스크톱 메모와 체크리스트는 XP 스타일의 흰 문서·목록 영역과 하단 상태
표시줄을 사용합니다. 메모는 작성·미리보기 탭을 제공하며, 체크리스트는 완료
개수와 반복 주기를 하단에 표시합니다. 편집·저장 중에는 주기 대신 현재 상태를
표시합니다. 활동 기록은 시간·항목·동작 열로 조회하고 같은 창에서
보관 기간을 설정합니다. 게스트에게는 읽기 전용 상태가 표시됩니다.
모바일은 기존 Android 스타일을 유지합니다.

## 파일 시스템

- D1이 바탕 화면·내 문서·하위 폴더 계층과 파일 메타데이터를 관리합니다.
- R2는 일반 파일 원본과 생성된 썸네일 바이트를 저장합니다.
- 프로그램 문서는 D1에만 저장합니다.
- 폴더 생성, 파일·폴더 업로드, 다운로드, 이름 변경과 이동을 지원합니다.
- 다중 선택과 드래그 앤 드롭으로 항목을 함께 이동하거나 삭제할 수 있습니다.
- 폴더별 이름·날짜·종류·크기 정렬 설정을 저장합니다.
  별도 설정이 없는 폴더는 만든 날짜 내림차순이며, 폴더를 먼저 표시합니다.
- 지원 파일은 뷰어·메모장으로 열고, 미지원 형식은 확인 후 다운로드합니다.
- 휴지통 이동, 복원, 영구 삭제와 전체 비우기를 지원합니다.
  서버 항목은 휴지통 아이콘이나 열린 휴지통 창의 목록 영역에 드롭할 수 있습니다.
- 단일 파일은 직접 다운로드하고 여러 파일·폴더는 ZIP으로 스트리밍
  다운로드합니다.

파일이나 폴더를 이름 변경하거나 이동해도 R2 객체 키는 바뀌지 않습니다.
R2의 공개 `r2.dev` 접근은 사용하지 않습니다. 기존 데이터와 API 호환성을
위해 내부 저장소의 `widget` 명칭은 유지합니다.

여러 항목의 ZIP 다운로드는 File System Access API를 지원하는 최신 데스크톱
Edge·Chrome이 필요합니다. 다운로드가 끝날 때까지 페이지를 열어 두어야 하며
프로그램 문서는 ZIP에서 제외됩니다.

목록은 페이지 단위로 불러옵니다. 데스크톱의 `Ctrl+A`는 서버 폴더 전체가
아니라 현재까지 불러온 항목만 선택합니다.

## 데이터 저장

| 저장소 | 역할 |
| --- | --- |
| D1 | 폴더 계층, 파일 메타데이터, 프로그램 내용·배치, 체크리스트 로그, 모바일 설정, 이미지 API 프로필·수신 기록과 게스트 공개 설정 |
| R2 | 일반 파일 원본과 생성된 썸네일 |
| 브라우저 `localStorage` | 모바일에서 작성 중인 프로그램 초안 하나와 소유자 모드 재접속 힌트 |

모바일 배경 파일이나 이를 포함한 폴더를 휴지통으로 보내면 설정이 해제되고
기본 Android 배경으로 돌아갑니다.

저장소 상태 프로그램은 열 때와 수동 새로 고침 시에만 소유자 전용
`GET /api/storage/status`로 사용량을 측정합니다. 표시는 현재 스냅샷을
기준으로 한 참고치이며 월 청구량이나 정확한 잔여 무료량이 아닙니다.

## 현재 지원하지 않는 기능

- PDF·Office 문서 미리보기와 일반 파일 내용 편집
- 파일 검색
- 공유 링크

미디어 형식은 [미디어 지원 문서](./MEDIA_SUPPORT.md), 게스트 화면은
[게스트 공개 문서](./GUEST_ACCESS.md)를 참고하세요.

### 체크리스트 반복 주기

소유자는 데스크톱 도구 모음의 `반복 설정`에서 일간·주간·월간을 선택한다.
기본은 일간이며 한국 시간 매일 0시·월요일 0시·매월 1일 0시를 경계로 한다.
초기화 작업 없이 현재 기간의 상태만 조회한다. 열린 화면은 경계 시각과
포커스 복귀 시 재조회하며 모바일·게스트도 같은 주기와 체크 시각을 표시한다.
주기 변경 시 현재 체크와 시각을 유지하고 새 주기의 다음 경계부터 미체크가 된다.
체크 시각은 서버 기준이며 해제하면 숨기고 재체크하면 갱신한다.
`PATCH /api/widgets/:id/checklist`의 본문은 `{ repeatCycle: "daily" | "weekly" | "monthly" }`이다.
응답에는 `repeatCycle`, 항목별 `checkedAt`(ISO 시각 또는 null)이 추가된다.
기존 프로그램 종류 `daily-checklist`와 파일명은 호환성을 위해 유지한다.

### 파일 목록 갱신

폴더와 휴지통은 같은 위치를 새로 고칠 때 기존 목록을 유지하면서 이미 읽은
페이지 수만큼 순차 조회하고, 모두 성공하면 한 번에 교체합니다. 남아 있는
항목의 선택과 스크롤 위치를 유지하며, 폴더 이동과 명시적인 정렬 변경은
초기화합니다. 일시적인 조회 실패에는 기존 목록과 다시 시도 버튼을 표시하고,
접근 거부 또는 대상 삭제가 확인되면 목록을 숨깁니다.

더 보기 결과의 중복 ID는 한 번만 표시합니다. OFFSET 기반 조회이므로 다른
기기나 이미지 API에서 목록을 변경하는 동안 발생하는 누락이나 여러 페이지의
동일 시점 일관성을 보장하지 않습니다. 이 경우 수동 새로 고침으로 다시 읽습니다.
자동 폴링이나 포커스 복귀 시 자동 갱신은 추가하지 않습니다.

### 영구 삭제 실패 복구

영구 삭제는 휴지통 최상위 항목에 시작 시각을 기록한 다음 원본·썸네일과 DB를
정리합니다. 중간 실패 항목은 데스크톱·모바일 휴지통에 “삭제 미완료 · 복원 불가”로
표시됩니다. 이 표시는 현재 요청의 실행 여부가 아닙니다. 원본이 일부 남아 있어도
복원할 수 없으며, 데스크톱의 영구 삭제 명령으로 남은 정리를 다시 실행합니다.
휴지통 비우기는 첫 실패에서 중단하고, 재실행하면 남은 항목을 처리합니다.
자동 복구나 백그라운드 삭제 작업은 없습니다.

### 업로드 중단과 재시도

데스크톱 전송 창에서 중단하면 대기 중인 폴더 생성·파일 전송을 시작하지 않습니다.
이미 실행한 요청은 완료를 기다리며 성공한 항목은 그대로 남습니다. 결과 창에서
“남은 항목 다시 시도”를 누르면 실패·미시작·상위 폴더 실패로 건너뛴 항목만 다시
실행합니다. 확인된 성공 파일은 제외하고 성공한 폴더의 서버 ID를 재사용합니다.
대상 폴더가 없어지면 오류를 표시하며 다른 위치로 보내지 않습니다.

서버에 저장된 뒤 응답만 유실되면 성공 여부를 확인할 수 없으므로 재시도로 같은
내용이 중복 추가될 수 있습니다. 파일 참조와 작업 상태는 현재 화면의 메모리에만
보관하며 결과 창 닫기·화면 종료 시 사라집니다. 미완료 전송이 남아 있으면 재시도하거나
결과 창을 닫은 뒤 새 전송을 시작할 수 있습니다. 진행 중 요청 취소와 서버 중복 방지는
지원하지 않습니다. 모바일 업로드는 이번 범위에 포함하지 않습니다.
